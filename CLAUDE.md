# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Nemi is a Go static site generator CLI. It compiles Markdown + Go HTML templates into plain HTML. Users run `nemi new <name>` to scaffold a site, then `nemi build` / `nemi serve` inside that site directory.

This repo is the **generator** itself — not a generated site. The `scaffold/` directory contains the template that gets copied to new sites.

## Commands

```bash
go run . <command>                        # run without building (e.g. go run . build)
go build -o nemi .                        # build the binary
go test ./...                             # run all tests
go test -run TestName ./internal/<pkg>    # run a single test
go vet ./...                              # lint
```

CLI surface (run via `go run . <cmd>` during development):

```bash
nemi new <name>                  # scaffold a new site into ./<name>
nemi new post "Title" [-s sec]   # scaffold a draft post (default section: blog)
nemi build [-D]                  # build content/ → public/ (prints "Built N pages in Xms")
nemi serve [-D]                  # dev server on :3000 + live reload
nemi check [-D]                  # content linter (broken links/assets, dup URLs, missing titles)
nemi version                     # print version (set via -ldflags "-X github.com/thisisbalu/nemi/cmd.version=...")
nemi migrate hugo <src> [dest]   # convert a Hugo site (dest defaults to <src>-nemi)
nemi migrate jekyll <src> [dest] # convert a Jekyll site
```

Both `build` and `serve` accept `--drafts` / `-D` to include `draft: true` pages. `nemi new post` reserves `post` as a subcommand name (a site literally named `post` can't be made via `nemi new post`). In `serve`, a failed rebuild pushes an `error:`-prefixed SSE message that the injected client renders as a full-screen overlay (see `scaffold/layouts/base.html`); successful builds push `reload`. `build.Run` returns `(Stats, error)` where `Stats.Pages = len(renderer.Rendered())`.

## Architecture

The build pipeline (triggered by `nemi build` or `nemi serve`) flows through these packages:

1. **`internal/config`** — decodes `nemi.toml` into `Config` (Title, BaseURL, Description, Author, Pages, Menu). `Load` sorts `[[menu]]` items by `weight`; `MenuItem.IsExternal()` is true for `external = true` or http(s) URLs. The scaffold nav ranges over `.Site.Config.Menu` (the older `[pages]` bools remain in the struct for migrate compatibility but no longer drive nav).
2. **`internal/content`** — walks `content/`, parses YAML frontmatter + Goldmark Markdown for each `.md` file. **Resolved cross-links:** after all pages load, `resolveRefs` rewrites `href="@/<content-relative-path>.md"` link destinations (e.g. `[x](@/blog/post.md)`) to the target page's output URL, preserving any `#fragment`. The ref key is the source path under `content/` exactly as written (extension included); a ref whose target doesn't exist makes `content.Load` return an error, so `build`/`check` fail on dangling cross-links instead of shipping 404s. Layout is resolved by `resolveLayout()`: slug maps to named layouts (home, about, resume, now, uses, etc.), sections become `<section>-list` / `<section>-single`, everything else falls back to `single`. A `layout:` frontmatter key overrides this. A `slug:` key overrides the output path/URL only (layout and section are still resolved from the file's location first, then the slug is applied — so URL overrides never change which template renders). Draft pages are excluded unless `--drafts` is passed.
3. **`internal/renderer`** — loads templates per page from the user's `layouts/` dir. Falls back to `list.html` for `-list` layouts, `single.html` for everything else. Templates are rendered with `ExecuteTemplate("base", data)`. The `TemplateData` struct (`Site`, `Page`, `ServeMode`) is what templates see. Sections without an `_index.md` get auto-generated list pages. **Partials** in `layouts/partials/` are read once per build (`loadPartials`) and parsed into every page's template set, named by their path under `partials/` minus `.html` (so `partials/icons/logo.html` → `{{template "icons/logo" .}}`). A missing `partials/` dir is not an error. **Tag pages** are auto-generated by `renderTags`: a `/tags/<urlize(tag)>/` term page per tag (layout `tag-list` → `list.html` fallback, posts in `.Pages`) plus a `/tags/` index (layout `tags`, term pages in `.Pages` each carrying their posts for counts). Slugs already present in content are not overwritten; no tags → no `/tags/`. **Pagination** (`renderListPage`): any `IsSection` page with more than `Config.Paginate` items (default `defaultPageSize` = 10) is split — page 1 at the base URL, pages 2+ at `<url>page/<n>/`. Each generated page gets `.Pages` sliced to that page plus a `.Paginator` (`PageNumber`, `TotalPages`, `TotalItems`, `PrevURL`, `NextURL`). All three list sources (section `_index`, auto-generated section lists, tag pages) route through `renderListPage`.
4. **`internal/data`** — `Load("data")` walks the site's `data/` dir, decoding `.yaml`/`.yml`/`.toml`/`.json` into a nested `map[string]any` keyed by path (`data/team/lead.json` → `.Site.Data.team.lead`). Missing dir → empty map. All decoders unmarshal into `any`, so values reach templates as maps/slices/scalars.
5. **`internal/build`** — orchestrates the above: deletes `public/`, runs renderer, writes `sitemap.xml` and `feed.xml`, copies `static/` flat into `public/`. Loads config, content, and data into `content.Site{Config, Pages, Data}`. The sitemap (`internal/sitemap`) is built from `renderer.Rendered()` — every page the renderer wrote, including generated section/tag/paginated pages — with URLs made absolute against `baseURL` (404 excluded). The RSS feed (`internal/feed`) is built from the content `pages` (not generated pages): the `blog` section's posts, newest-first, capped at 20; no posts → no `feed.xml`. A permissive `robots.txt` (advertising the sitemap) is written by `writeRobots`. **Search** (`internal/search`) writes a JSON index of the content pages (title/url/tags/summary/plain-text body) to `public/search-index.json` — built in *every* mode (cheap), gated by `[search] disable`. It's a pure-Go, zero-dependency alternative to Pagefind: the scaffold's `partials/search.html` ships a client-side modal (open with the header ⌕, `/`, or ⌘/Ctrl-K) that fetches the index once and filters/ranks in the browser (title>tags>body), suited to personal-site scale. `copyStatic` runs last, so a user's `static/robots.txt` (or `sitemap.xml`/`feed.xml`) overrides the generated one. Each page's absolute `Permalink` (for `<link rel="canonical">`) is set in `renderPage` from `baseURL` + `URL`, covering all page types through that single choke point. **Social cards & SEO meta**: `scaffold/layouts/partials/head.html` emits OpenGraph + Twitter Card tags and a schema.org JSON-LD block (`BlogPosting` for section articles, `WebSite` otherwise) on every page. The JSON-LD is built by the `jsonLD` template func (`internal/renderer/funcs.go`) via `encoding/json` so it's always valid/escaped — don't hand-write JSON in the template. Each page's `og:image` is its auto-generated social card: `internal/ogimage` renders a 1200×630 PNG (title + site name, near-monochrome, embedded Go fonts — pure Go, no cgo/font files), and the production-only `generateOGImages` build pass writes one per rendered page to `public/og/<slug>.png` (path from `content.OGImagePath`, the single source of truth shared with the renderer, which sets the absolute `Page.OGImage`). Best-effort + `[og] disable = true` to skip. **Responsive images** (`internal/images`, pure Go — `image` + `golang.org/x/image/draw`, no cgo so it cross-compiles under `CGO_ENABLED=0`) run as a production-only post-pass (`optimizeImages`, after `copyStatic`, before minify). It rewrites every `<img>` over a local raster source (`/foo.jpg|.jpeg|.png`) into a responsive one: generates resized variants (`foo-<w>.jpg`) for each `Config.Images.Widths` smaller than the source, and emits `srcset` + `sizes` + intrinsic `width`/`height` (kills layout shift) + `loading="lazy"` + `decoding="async"`, preserving `alt`/`title`. Best-effort: a source that can't be decoded (or SVG/GIF, or external, or already has a `srcset`) is left untouched. Sources are processed once per build (cached by URL). Zero-config via defaults applied in `config.Load` (widths 480/800/1200, quality 82, sizes `(max-width: 960px) 100vw, 960px`); `[images] disable = true` turns it off. **WebP/AVIF are intentionally out of scope** (need cgo or a wasm runtime). **Subpath deploys** (`applyBasePath`, after the image pass, before minify): when `baseURL` has a path component (e.g. `https://thisisbalu.github.io/nemi/`), `config.Load` derives `Config.BasePath` (`/nemi`), and this pass rewrites root-relative `href`/`src`/`srcset`/CSS `url()` in the built HTML/CSS to sit under it — covering theme assets, page links, `@/` links, and user-authored links with **no template changes** (the zero-config principle). Protocol-relative (`//`) and absolute (`https://`) URLs are untouched; sitemap/feed/canonical/`og:image` are already correct since they build on the subpath-bearing `baseURL`. Search index URLs are prefixed in `search.Build`, and the search JS reads the prefix from `window.__nemiBase` (set in `head.html`). `BasePath` is forced empty in `serve` so dev stays at root. **Minification** (`internal/minify`, tdewolff) runs as the final post-pass (`minifyTree`) over `public/` for `.html`/`.css`/`.js` — but only for production builds (`!serveMode`), so `serve` output stays readable and rebuilds stay fast. It's best-effort: a file that fails to minify is left untouched. Done in `build`, not the renderer, so the renderer stays pure and its output is unminified (tests rely on this).
6. **`cmd/serve`** — wraps build in a file-watcher loop (fsnotify, 150ms debounce) over `content/`, `layouts/`, `static/`, `data/`, with SSE live-reload via `/__nemi_reload`.
7. **`internal/migrate`** — `Hugo(src, dst)` and `Jekyll(src, dst)` convert existing sites to Nemi format. Hugo handles TOML/YAML/JSON frontmatter; Jekyll maps `_posts/YYYY-MM-DD-slug.md` → `content/blog/slug.md`.
8. **`internal/check`** (`nemi check`) — content linter. Loads content (no build), builds the valid-internal-path set (page URLs + section + tag pages + `static/` files), and scans each page's rendered HTML (`href`/`src` via regex on Goldmark's quoted output) for broken internal links/assets. Also flags duplicate URLs (error) and missing titles (warning). `cmd/check.go` prints issues and exits non-zero on any error. URL slugs use `content.Urlize` (shared with the renderer's `urlize` template func and tag generation — single source of truth).

## Scaffold embedding

`scaffold/scaffold.go` embeds the entire `scaffold/` directory (including hidden files and subdirs) as `scaffold.FS`. `cmd/new` walks that FS and copies everything to the new site directory. Any file added to `scaffold/` is automatically included.

The scaffold includes AI context files for generated sites: `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`, `.github/copilot-instructions.md`. Edits to these affect what AI assistants see when working inside a generated site.

## Key invariants

- `public/` is deleted on every build — never write to it directly.
- Template execution always starts at the `"base"` named template, which must `{{block "content" .}}` for layout templates to inject into.
- `.Page.Content` is `template.HTML` (already sanitized) — output with `{{.Page.Content}}`, not `{{html .Page.Content}}`.
- `nemi.toml` is TOML; content frontmatter is YAML.
- Draft pages (`draft: true`) are excluded during `content.Load` — they never reach the renderer.
- The slug `404` is special: it writes to `public/404.html` (not `public/404/index.html`).
- Template functions live in `internal/renderer/funcs.go` (`funcMap`): `not`, `now`, `dateFormat`, `lower`, `upper`, `title`, `urlize`, `truncate`, `first`, `where`, `sortByDate`. Add new ones there, not inline.

## Page fields available in templates

`TemplateData` exposes `.Site` (with `.Config.Author`, `.Config.Pages`, `.Config.Title`, etc.) and `.Page`. Less obvious `Page` fields:

| Field | Frontmatter key | Purpose |
|---|---|---|
| `Tech` | `tech` | `[]string` — technology list for project pages |
| `GitHub` | `github` | URL string for project source |
| `Live` | `live` | URL string for live demo |
| `Featured` | `featured` | bool — highlight on list pages |
| `Type` | `type` | arbitrary string for custom template branching |
| `Pages` | — | populated automatically on section list pages |
| `IsSection` | — | true for `_index.md` / `index.md` files |
| `TOC` | — | `template.HTML` nested `<nav class="toc">` from h2/h3; empty if <2 headings |
| `Headings` | — | `[]Heading{Level, ID, Text}` in document order (h2/h3) |
| `Summary` | — | auto excerpt: first paragraph's plain text, ≤60 words (`summarize`) |
| `WordCount` / `ReadingTime` | — | computed from `plainText`; reading time = ceil(words/200) |
| `Math` | `math` | bool — load KaTeX (CSS in head, auto-render JS in base) on this page |
| `Mermaid` | — | bool — auto-set true when the page contains a ```mermaid block; loads mermaid.js |

Markdown rendering (`internal/content`) uses a shared, configured `md` goldmark instance: **Chroma syntax highlighting** (class-based, `github-dark` — token CSS ships in `scaffold/static/style.css`), **`WithAutoHeadingID()`** (stable heading ids → deep links + TOC), and **GFM + Footnote + Typographer** extensions (tables, strikethrough, task lists, autolinks, footnotes, smart quotes). `parseFile` parses to an AST once, then renders and walks it for the TOC — don't revert to `goldmark.Convert` or the TOC breaks.

**Mermaid** (`internal/content`): a goldmark AST transformer (`mermaidTransformer`, priority 100) rewrites every ```mermaid fenced block into a custom `mermaidBlock` node *before* the highlighter runs, and `mermaidRenderer` emits it as `<pre class="mermaid">` with the source escaped verbatim (Chroma never tokenizes it). `Page.Mermaid` is set by detecting that marker in the rendered HTML; `base.html` then loads mermaid.js (theme-aware) only on those pages. **Math**: client-side KaTeX auto-render — no server-side math parsing. `math: true` frontmatter sets `Page.Math`; `head.html` adds the KaTeX CSS and `base.html` the auto-render JS (delimiters `$$…$$`, `\[…\]`, `\(…\)`, `$…$`), both gated so non-math pages stay lean.

**Data-driven pages** (al-folio-style, via `internal/data` → `.Site.Data`): `layouts/resume.html` renders a CV from `data/cv.yaml` (`experience`/`education`/`skills`, optional `pdf` download) alongside the page's prose. `layouts/publications.html` is an **opt-in academic** feature (off by default) — it renders `data/publications.yaml` (entries grouped by `year`, each with `title`/`authors`/`venue`/`selected` and `url`/`pdf`/`code` links); the slug `publications` resolves to it, but no nav/content page ships by default, so it stays dormant until a user adds `content/publications.md`. The home page surfaces a **news feed** from the `updates` section (latest 4, date-led).

`Site.Config.Pages` is a struct of bools (from `[pages]` in `nemi.toml`) controlling which nav sections are enabled.
